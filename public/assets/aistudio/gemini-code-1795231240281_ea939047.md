# Project Specification: Van Spare Parts Inventory & Claim Tracker

## 1. Project Overview
Build a Mobile-First Web Application to manage spare parts inventory inside company service vans. The goal is to create a closed-loop workflow between **Technicians** (who consume parts at customer sites) and **Admins** (who manage restocking/claims and monitor inventory levels) so that every van maintains its standard full inventory (Par Level) at all times.

## 2. Tech Stack & Architecture
- **Frontend:** React (Vite), TypeScript, Tailwind CSS
- **Icons:** Lucide React
- **State & Persistence:** React State synced with `localStorage` (structured cleanly so it can be easily swapped with Firebase Firestore or Supabase later).
- **Design System:** Clean, high-contrast industrial/field-service UI. Large touch targets (minimum 44px height) for technicians working on mobile phones.

## 3. Core Data Models

### 3.1 Van (`Van`)
- `id`: string (e.g., `"van-01"`)
- `name`: string (e.g., `"Van 01 - Ah Meng"`, `"Van 02 - Jason"`)
- `plateNumber`: string (e.g., `"JVA 1234"`)

### 3.2 Spare Part Item (`VanInventoryItem`)
Each van has its own list of items with a **Par Level (Target Quantity)**:
- `id`: string
- `vanId`: string
- `partName`: string
- `sku`: string
- `category`: string (e.g., `"Electrical"`, `"Plumbing"`, `"Cooling"`)
- `targetQty`: number (Standard full load required in the van)
- `currentQty`: number (Actual quantity currently in the van)
- *Computed Property:* `deficitQty = targetQty - currentQty` (Amount needed to claim/restock)

### 3.3 Transaction Log (`TransactionLog`)
- `id`: string
- `timestamp`: string (ISO format)
- `vanId`: string
- `vanName`: string
- `partId`: string
- `partName`: string
- `type`: `'CONSUME'` | `'RESTOCK'`
- `qty`: number
- `customerRef`: string (Required for `'CONSUME'`, e.g., Customer Name or Job Order #)
- `status`: `'PENDING_CLAIM'` | `'RESTOCKED'` | `'COMPLETED'`

## 5. User Roles & Functional Requirements

### Global Navigation Header
- App Title & Logo: **VanSpare Sync**
- **Role Switcher Tabs:** `[ Technician View ]` vs `[ Admin View ]`
- **Reset Demo Data Button:** Small utility button in footer/settings to restore initial seed data.

---

### View A: Technician View (Mobile-Optimized Field Operations)
1. **Van Selector:** Prominent dropdown at the top to select which Van the technician is operating.
2. **Readiness Status Banner:**
   - Displays Van Readiness Percentage: `(Total Current Qty / Total Target Qty) * 100%`.
   - If `deficit > 0`, show an alert badge: `"Action Needed: [X] parts missing (Pending Claim)"`.
   - If `deficit === 0`, show a green badge: `"100% Ready - All Spares Full"`.
3. **Quick Log Usage Form ("Use Part for Customer"):**
   - **Select Part:** Dropdown showing part name and `(Current: X / Target: Y)`. Disable parts where `currentQty === 0`.
   - **Quantity Used:** Stepper input (`-` / `+`), default `1`, min `1`, max `currentQty`.
   - **Customer / Job ID:** Text input (Required, placeholder: `"e.g., Mr. Tan / Job #1042"`).
   - **Submit Button:** `"Confirm Usage & Notify Admin"`
     - *Action:* Deducts `qty` from `currentQty`, creates a `CONSUME` log with status `PENDING_CLAIM`, and triggers a clear toast notification: `"Recorded! Claim [Qty]x [Part Name] from Admin when back at base."`
4. **Current Van Checklist:**
   - Searchable/filterable list of all parts assigned to the selected van.
   - Visual progress bar or badge for each item (`currentQty / targetQty`).
   - Highlight rows where `currentQty < targetQty` in soft red/amber with a `"Need +[deficitQty]"` tag.

---

### View B: Admin View (Warehouse & Inventory Control)
1. **KPI Summary Cards (All Vans):**
   - Total Vans Monitored
   - Total Pending Claims (Total units needing restock across all vans)
   - Vans at 100% Readiness
2. **Restock & Claim Queue (Priority Action Table):**
   - Filters/displays all parts across all vans where `currentQty < targetQty` (or active `PENDING_CLAIM` items).
   - Columns: `Van Name`, `Part Name (SKU)`, `Current / Target`, `To Restock (Deficit)`, `Related Customer Refs`, and `Action`.
   - **Action Button:** `[ Confirm Restock (Fill to Par) ]`
     - *Action:* Sets `currentQty = targetQty` for that item, marks related `PENDING_CLAIM` logs as `RESTOCKED`, and creates a `RESTOCK` audit log entry.
3. **Par Level Configuration (Manage Standard Load):**
   - Select any Van to view/edit its standard spare parts list.
   - Allow Admin to edit `targetQty` (Par Level) or add a new spare part to a Van.
   - Allow Admin to add a new Van to the fleet.
4. **Transaction & Audit History:**
   - Chronological table of all `CONSUME` and `RESTOCK` events.
   - Filterable by Van and Transaction Type (`All`, `Consumed`, `Restocked`).
   - Shows timestamp, Van, Part, Qty, Customer/Job ID, and Status badge.

## 6. UI/UX & Edge Case Rules
- **Validation:** Prevent technicians from logging usage exceeding `currentQty`. Prevent submitting without a Customer/Job ID.
- **Status Colors:**
  - `currentQty === targetQty`: Emerald Green (`bg-emerald-100 text-emerald-800`)
  - `currentQty > 0 && currentQty < targetQty`: Amber (`bg-amber-100 text-amber-800`)
  - `currentQty === 0`: Rose Red (`bg-rose-100 text-rose-800`)
- **Responsive Layout:** Tables on Admin View should cleanly stack or scroll horizontally on smaller screens.
